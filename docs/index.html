Abstract Content teams managing large page portfolios cannot manually review every page each week. This paper asks: which pages deserve attention first? Using an anonymized dataset of 30,000 pages from the FlyRank ML Internship, a Random Forest classifier was trained on non-leaking behavioral and structural signals to predict which pages are experiencing genuine click-drop decay. 01 — Introduction

The Problem

Content teams at search-focused companies manage hundreds or thousands of published pages. Each week, some fraction of those pages are quietly losing search impressions, dropping in average position, or bleeding click-through rate — but without a systematic review, nobody notices until the damage is severe.

The decision this project supports is simple: which pages should a reviewer look at first this week? The output is not an automated publishing decision. It is a ranked list — a prioritized queue — that puts the most urgent pages at the top so human review time is spent where it matters most.

The cost of getting this wrong runs in both directions. Flagging a healthy page wastes expert reviewer time on a false alarm. Missing a genuinely declining page allows it to keep losing traffic for weeks before anyone notices, making recovery harder and more expensive.

02 — Data

Dataset

The analysis uses the FlyRank ML Internship starter dataset: 30,000 anonymized pages with 44 columns covering search impressions, clicks, sessions, CTR, average position, content age, word count, engagement rate, and trend signals. Data spans a rolling 90-day performance window with 30-day trend comparisons.

Columns deliberately excluded

The following columns were removed before any model training to prevent label leakage:

  • trend_direction, trend_pct — directly encode the target variable
  • clicks_last_30d, clicks_prev_30d — used to construct the label
  • sessions_last_30d, sessions_prev_30d — same window as the label
  • client_id — used for grouping only, never as a feature

Safe features retained

ctr, avg_position, impressions_prev_30d, engagement_rate, content_age_days, word_count, days_since_last_update, plus engineered ratios ctr_to_position_ratio and engagement_density.

Public-safety note: No client names, raw URLs, private queries, or identifying details appear anywhere in this paper or the associated repository.
03 — Methodology

Approach

Label definition

A page is labeled a decay candidate if clicks_last_30d < clicks_prev_30d — a measurable drop in clicks from one 30-day window to the next. This is observable without using any label-derived columns, making it a clean, non-leaking proxy for genuine traffic loss.

Baseline rule

A transparent hand-written rule was built first: flag any page with content_age_days > 180 and declining impression volume. This rule is interpretable and deployable without any ML infrastructure, making it a fair comparison point.

Model

A Random Forest Classifier was trained alongside Logistic Regression as a secondary baseline. Logarithmic scaling was applied to skewed volume metrics. Hyperparameter tuning used RandomizedSearchCV optimizing Macro F1 to handle class imbalance.

Validation design

GroupKFold cross-validation was used, splitting strictly on client_id. This ensures no pages from the same client appear in both training and validation folds — a stricter and more honest design than a random 80/20 split, which would leak within-client correlations across the boundary.

Error analysis

Out of the top 50 ranked pages, 13 were false positives. These were concentrated in high-traffic pages with modest CTR that held stable click volume rather than dropping. The model leans heavily on impression scale when prioritizing risk — a known limitation when dealing with large-impression pages that are stable but not growing.

05 — Limitations

Honest Framing

All findings in this paper are observational and directional. This model does not establish causation between content refresh actions and traffic recovery. The label (clicks_last_30d < clicks_prev_30d) is a proxy for decay, not a verified ground truth.

The dataset is a single anonymized snapshot from one company's client portfolio. Results may not generalize to all industries, content types, or search markets. The model is a decision-support tool, not an automated publishing system.

Precision@50 of 0.74 means 13 of the top 50 recommendations are false positives — pages that would not benefit from a refresh. Reviewers should apply judgment rather than treating the ranked queue as instructions.

06 — Recommendations

Action Playbook

Based on predicted decay scores, content teams should apply the following tiered response:

Score > 0.80

Priority Refresh — Top 50 Queue

Update core content sections, refresh meta title and description tags, check for broken links. These pages are observed to be experiencing active click-drop decay and have high impression volume at stake.

Score < 0.35

Protect and Maintain

Do not modify URLs, core text, or structure on high-performing evergreen pages regardless of content age. Unnecessary updates risk destabilizing established search equity and ranking stability.

Score > 0.80
Low impressions

Prune or Merge

Identify persistent dead-weight URLs that fail to engage users or capture search visibility. Consolidate via 301 redirects to stronger canonical pages or prune to preserve crawl budget.
